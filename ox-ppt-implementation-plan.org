#+TITLE: Org-Mode to PowerPoint (PPTX) Exporter Implementation Plan
#+AUTHOR: Implementation Plan
#+DATE: 2025-11-20

* Overview

This document outlines the implementation plan for =ox-ppt=, an Emacs Lisp package that exports Org-mode documents to Microsoft PowerPoint (PPTX) format.

** Goals

- Export Org-mode documents to valid PPTX presentations
- Support core Org-mode elements (headings, lists, tables, images, code blocks)
- Maintain semantic structure from Org to PowerPoint slides
- Provide customizable slide layouts and themes
- Use =esxml= for clean XML generation

** Project Inspiration

- [[https://github.com/emacsmirror/org-re-reveal][org-re-reveal]]: Org to reveal.js exporter (architectural reference)
- [[https://orgmode.org/worg/dev/org-export-reference.html][Org Export Reference]]: Official export backend documentation

* Understanding the Target Format

** PPTX File Structure

A PPTX file is a ZIP archive containing XML files following the Office Open XML (OOXML) PresentationML specification.

*** Core Components

1. =[Content_Types].xml= - Defines content types for all parts
2. =_rels/.rels= - Package-level relationships
3. =ppt/presentation.xml= - Main presentation file (references slides)
4. =ppt/slides/= - Directory containing individual slide XML files
5. =ppt/slideLayouts/= - Slide layout templates
6. =ppt/slideMasters/= - Master slide definitions
7. =ppt/theme/= - Theme files (colors, fonts, effects)
8. =ppt/_rels/= - Relationship files linking components

*** Key Characteristics

- Each slide is a separate XML file
- Slides reference layouts, which reference masters
- Relationships managed through =.rels= files
- All XML uses specific PresentationML namespaces

** PresentationML Structure

*** Essential Namespaces

#+begin_src xml
xmlns:a="http://schemas.openxmlformats.org/drawingml/2006/main"
xmlns:p="http://schemas.openxmlformats.org/presentationml/2006/main"
xmlns:r="http://schemas.openxmlformats.org/officeDocument/2006/relationships"
#+end_src

*** Slide Content Organization

- Slides contain shape trees (=<p:spTree>=)
- Shapes include text boxes, images, tables, charts
- Text uses DrawingML for formatting
- Positioning uses EMU (English Metric Units): 914,400 EMUs = 1 inch

** DrawingML: The Visual Rendering Layer

DrawingML (Drawing Markup Language) is the vector graphics and text formatting language that serves as the visual backbone of Office Open XML documents. It's not standalone—it's embedded within PresentationML (PowerPoint) to handle all visual elements.

*** What DrawingML Handles

DrawingML is responsible for:
- Shape appearance and positioning
- Text formatting within shapes
- Colors, themes, fonts, and styles
- Graphics, charts, tables, and diagrams

*** Core Components

**** Shapes and Positioning

Every visual element on a slide is a shape with a transform (=<a:xfrm>=):

#+begin_src xml
<a:xfrm>
  <a:off x="914400" y="914400"/>    <!-- Position: 1" from left, 1" from top -->
  <a:ext cx="7315200" cy="914400"/> <!-- Size: 8" wide, 1" tall -->
</a:xfrm>
#+end_src

Key units: EMUs (English Metric Units)
- 914,400 EMUs = 1 inch
- 12,700 EMUs = 1 point

**** Text Hierarchy

Text in shapes follows a hierarchical structure:

#+begin_example
Shape
└── Text Body (<a:txBody>)
    ├── Body Properties (<a:bodyPr>) - columns, margins, wrapping
    └── Paragraphs (<a:p>)
        ├── Paragraph Properties (<a:pPr>) - alignment, spacing, bullets
        └── Text Runs (<a:r>)
            ├── Run Properties (<a:rPr>) - bold, italic, size, font
            └── Text Content (<a:t>)
#+end_example

**** Text Formatting

Unlike WordprocessingML where formatting is in child elements, DrawingML uses *attributes* on =<a:rPr>=:

#+begin_src xml
<a:r>
  <a:rPr sz="2400"        <!-- 24pt font size -->
         b="1"            <!-- bold -->
         i="1"            <!-- italic -->
         u="sng"          <!-- underline: single -->
         baseline="30000"> <!-- superscript: 30% -->
    <a:latin typeface="Arial"/>
    <a:solidFill>
      <a:srgbClr val="FF0000"/>  <!-- red text -->
    </a:solidFill>
  </a:rPr>
  <a:t>Hello World</a:t>
</a:r>
#+end_src

**** Lists and Bullets

Bullets and numbering are paragraph-level properties:

#+begin_src xml
<a:p>
  <a:pPr lvl="0">  <!-- indentation level -->
    <a:buFont typeface="Arial"/>
    <a:buChar char="•"/>  <!-- bullet character -->
  </a:pPr>
  <a:r>
    <a:t>First item</a:t>
  </a:r>
</a:p>
#+end_src

**** Themes

DrawingML defines themes (=<a:theme>=) that provide consistent styling:

#+begin_src xml
<a:theme>
  <a:themeElements>
    <a:clrScheme>     <!-- Color palette -->
    <a:fontScheme>    <!-- Font families -->
    <a:fmtScheme>     <!-- Fill/line/effect styles -->
  </a:themeElements>
</a:theme>
#+end_src

*** DrawingML in PPTX Files

DrawingML appears in multiple places within a PPTX file:

**** On Slides (=ppt/slides/slideN.xml=)

#+begin_src xml
<p:sp>  <!-- Presentation shape -->
  <p:spPr>  <!-- Shape properties -->
    <a:xfrm>  <!-- DrawingML transform -->
    <a:prstGeom prst="rect">  <!-- DrawingML geometry -->
  </p:spPr>
  <p:txBody>  <!-- Text body -->
    <a:bodyPr/>  <!-- DrawingML text properties -->
    <a:p>  <!-- DrawingML paragraph -->
  </p:txBody>
</p:sp>
#+end_src

**** In Theme Files (=ppt/theme/themeN.xml=)

Entirely DrawingML, defining colors, fonts, and format schemes.

**** In Layout/Master Slides

Templates that use DrawingML placeholders that individual slides inherit.

*** Key Characteristics

1. *Namespace*: =xmlns:a="http://schemas.openxmlformats.org/drawingml/2006/main"=
2. *EMU-based positioning*: Everything is measured in EMUs, requiring conversion from inches/points
3. *Attribute-heavy formatting*: Unlike HTML or WordML, most text formatting uses attributes, not nested elements
4. *Hierarchical styling*: Themes → Master → Layout → Slide (inheritance cascade)
5. *Verbose but structured*: DrawingML XML is very explicit—no defaults, everything must be specified

*** Implications for ox-ppt Implementation

When building the exporter, we must:

1. Generate DrawingML text structures from Org-mode text
2. Calculate EMU positions for layout
3. Handle the text hierarchy: paragraph → run → properties
4. Map Org formatting (bold/italic/code) to =<a:rPr>= attributes
5. Create shape geometries for text boxes, images, tables
6. Use =esxml= to generate these nested structures cleanly

The verbosity of DrawingML makes =esxml= particularly valuable—building these nested structures with S-expressions will be much cleaner than string concatenation.

** Phase 2: PPTX Generation with esxml

Use =esxml= to generate PresentationML XML:

** Phase 4: Org Element Mapping

*** 4.1 Headline to Slide Mapping

**** Title Slide

The first slide (title slide) is generated from document properties:

- =#+TITLE= - Main presentation title
- =#+SUBTITLE= - Optional subtitle
- =#+AUTHOR= - Presentation author (optional)
- =#+DATE= - Date (optional)
- =#+TITLE-BACKGROUND= - Background color or image for title slide

**** Content Slides

Default strategy:

- *Level 1 headlines* (=*=) → New slides (one headline = one slide)
- *Level 2+ headlines* (=**=, =***=, etc.) → Headings/subheadings within the current slide

Example:

#+begin_example
,#+TITLE: My Presentation
,#+SUBTITLE: An Overview
,#+AUTHOR: John Doe

,* First Slide
This is content for the first slide.

,** This is a heading within the slide
More content here.

,*** This is a subheading
Even more detail.

,* Second Slide
This becomes a new slide.
#+end_example

This mapping can be customized via =org-ppt-slide-level= variable if needed.

*** 4.2 Content Handling

| Org Element      | PowerPoint Representation        |
|------------------+----------------------------------|
| Paragraph        | Text box with paragraphs         |
| Plain list       | Bulleted/numbered text           |
| Table            | Table shape                      |
| Image            | Picture shape                    |
| Source block     | Text box with monospace font     |
| Quote block      | Text box with special formatting |
| Bold/Italic/Code | DrawingML text runs with format  |
| Links            | Hyperlinks (text or images)      |

*** 4.3 Special Org Keywords

**** Document-Level Keywords

These keywords control the title slide and global presentation settings:

#+begin_example
,#+TITLE: My Presentation Title
,#+SUBTITLE: Optional subtitle text
,#+AUTHOR: John Doe
,#+DATE: 2025-11-20
,#+TITLE-BACKGROUND: #4472C4
,#+PPTX_THEME: default
,#+PPTX_SLIDE_SIZE: standard
#+end_example

**** Slide-Level Properties

Individual slides can be customized via headline properties:

#+begin_example
,* Slide Title
:PROPERTIES:
:PPTX_LAYOUT: title_only
:PPTX_BACKGROUND: #ffffff
:PPTX_TRANSITION: fade
:PPTX_NOTES: Speaker notes here
:END:

Slide content goes here.
#+end_example

** Known Challenges

*** 1. Text Formatting Complexity

DrawingML text formatting is verbose. Need helper functions for:
- Text runs with formatting properties
- Paragraph properties (alignment, spacing, indentation)
- List bullet styles and numbering

*** 2. Positioning and Layout

Automatic layout of content shapes requires:
- Height calculation for text content
- Intelligent overflow handling
- Multi-column layouts

*** 3. Image Handling

Must handle:
- Various image formats (PNG, JPEG, SVG)
- Image embedding vs. linking
- Size and positioning
- SVG to raster conversion (if needed)

*** 4. Table Complexity

PowerPoint tables have:
- Cell-level formatting
- Borders and shading
- Column width calculations
- Cell merging (for Org table groups)

*** 5. PPTX Validation

Ensuring generated XML is:
- Well-formed
- Schema-compliant
- Compatible with PowerPoint and LibreOffice

** Fallback Strategies

- Start with simple layouts; add complexity iteratively
- Use text boxes for unsupported elements initially
- Provide warning messages for unhandled content
- Generate valid (if simple) output rather than failing

* Conclusion

This implementation plan provides a structured approach to developing =ox-ppt=, an Org-mode to PowerPoint exporter. By following the phased approach and leveraging =esxml= for XML generation, we can create a maintainable and extensible exporter that brings Org-mode's powerful document authoring to PowerPoint presentations.

The project draws inspiration from =org-re-reveal= while targeting the more complex PPTX format. Success will require careful attention to the PresentationML specification, but the modular architecture and clear milestones should make the implementation manageable.
